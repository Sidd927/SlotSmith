## 2. Claims that must not be strengthened without new evidence
- **Optimality.** FFD is *proved* minimal only within one A/B side class with sizes 2/6/12 (24 as two full baseplates). Group-level results are *tested*, not proved. No claim of minimum CIOCs or cabinets, and no "universal optimality".
- **Revisions.** No "minimum moves", "fewest moves" or "guaranteed" wording.
  - Repair is window-local.
  - Only 7 of 11 accepted windows were proven exact.
  - Results vary between runs: always show the **429–470** range, never a single number.
- **Coverage.** "100%" means *allocated or covered by a TQ*. Never write "100% allocated".
- **Official data.** No claim of official-data validation, official-template compatibility, or hidden-test performance.
- **Time savings.** None measured, so none claimed. Impact statements stay "expected".
- **Emerson comparison.** "No public tool found" must stay "found no public tool … internal tools may exist". Never "Emerson lacks" and never "better than Emerson".
- **Rules.** "Configurable" applies to existing rule parameters. New rule types may need code.
- **AI.** AI helpers are *planned*. No LLM runs today, and AI never places signals.
- **Scale.** 300 CIOCs is a specification maximum (PDS "Number of CIOCs per System: 300"), not a typical project size.
- **Adapters and other platforms:** "planned, not yet validated" / "untested".
- **Bottleneck language.** Do not reinstate "paperwork is now the bottleneck"; the PS supports "manual workflow burden".
